# Author a flame response to ImageGen

Open the **Flame · inference & replay** experiment in Workbench. It uses the scene's existing flame and the ordinary Properties controls.

1. Choose or capture A and B in **Author A/B looks in Properties**. Check the parameters that should travel together. The existing blend slider auditions the endpoints.
2. Save a reusable object under **Saved states & effects**. A **State** holds B, a **Transition** travels A → B, and an **Effect** rises toward B then returns to the underlying layers. Names are optional. Add objects to each phase, reorder them with the arrows, or disable/remove individual layers. Lower layers override overlapping parameters. Editing a saved object updates every layer using it.
3. Optionally tune a brighter or otherwise different peak in Properties, open **Flare when a preview appears**, and capture it. The checked parameters move toward that peak when a preview arrives, then settle back onto the continuing stage response.
4. Press **Replay** or scrub the recording. Replay reconstructs the parameter response; the fluid continues evolving. Pause keeps the current look. A replay preview is one scene history edit.
5. Click **Follow next ImageGen**, then use the normal **Generate** panel. The next run supplies real stage, step and preview events. **Latest ImageGen run** loads its observations for replay afterward. Arrangement edits pause replay/following; arm Follow again for a subsequent run.

Each transition/effect offers **Fit phase**, **Authored seconds**, or **Observed progress**, plus a duration multiplier. Fit uses the recorded phase span; ×1 fills it. Authored seconds uses the saved blend duration. Observed progress follows measured progress; unknown progress falls back to authored seconds without inventing a percentage. Live phases with unknown lengths also use authored seconds. Layer and global multipliers stretch responses; longer responses may be interrupted by the next phase. Finished always gets its full authored duration after inference completes.

Captured endpoints immediately select a compact name derived from their values and a portrait of the current evolved flame. A/B portraits and shared basin covers use the same front-facing domain framing. The capture borrows the view briefly and restores it without stepping or resetting the fluid. Cold fields or unavailable capture routes keep the saved settings and report a pending portrait. Saved states show B; transitions show both endpoints. Explicit blend and arrangement exports embed portraits for reopening on another machine; live replay retains only short image references.

The Properties basin browser shows shared covers. Save basin captures the current field; it never waits through a new simulation warmup. Older basins can be backfilled through `scripts/backfill-basin-portraits.mjs --output <receipt-directory> --steps 60` under Greenroom. The batch preserves authored grid and rendering settings, records current compatibility projection/clamps and appearance mode, and reports each missing or failed cover separately. Replay runs no inference; it does not reconstruct an evolved fluid checkpoint.

The initial recording is an illustrated demo, labelled as such. Klein's real intermediate previews are approximate latent RGB projections, not fully decoded intermediate images. Stages without known progress show no percentage.

**Save arrangement** writes objects, phase stacks, the recording with preview pixels, and the flare to one JSON file. **Open arrangement** restores it. A file without a recording says so; choose **Demo recording** or an observed run explicitly. New exports use `kaminos.inference-flame.v2`; v1 files import their stage recipes as phase-fitted transitions, with an authored-duration Finished transition. Older readers reject v2 instead of silently omitting its stacks. File export retains recordings across page sessions; the in-page event store is temporary. Preview computation is requested only when Follow is armed at generation admission. Pausing Follow stops observing previews; a pipeline that already received the callback can still perform its remaining preview work until generation ends.

For agent use, the same operations are available through `window.kaminosWorkbenchExperiments.invoke`: `response.assign`, `response.captureFlare`, `response.play`, `response.seek`, `response.pause`, `response.follow`, `response.export`, and `response.restore`. An experiment can open with `{arrangement, blend}` inputs, or `{arrangementUrl}` pointing to a saved JSON arrangement. The URL form fetches the exact file and reports failure rather than silently using the demo. Opening an arrangement does not automatically apply its looks; Replay or seeking applies them.

Object operations are `response.saveBlendObject`, `response.updateBlendObject`, `response.editObject`, `response.renameObject`, and `response.deleteObject`; direct `response.saveObject`/`response.updateObject` accept explicit recipes. Stack operations are `response.addLayer`, `response.updateLayer`, `response.moveLayer`, and `response.removeLayer`. `response.timeScale` sets the global duration multiplier. A saved object still used by a layer cannot be deleted. The retained direct-stage `response.assign` API continues observed-progress easing through unassigned successor phases.
