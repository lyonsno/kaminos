# Author a flame response to ImageGen

Open the **Flame · inference & replay** experiment in Workbench. It uses the scene's existing flame and the ordinary Properties controls.

The cockpit shows all six inference phases together. Select a saved picture card, then use **+** on its destination phase, or drag the card onto that phase. The phase's cards form its stack; later cards override shared parameters. Select an assigned card to enable, reorder, remove or change its timing in the single editor. A saved object can appear in several phases; editing its endpoints changes every use.

Use **▶** beside a phase to preview only that recorded span. It stops at the phase endpoint; Finished includes its full authored tail. Phases absent from the recording stay visible for authoring and say **Not in recording** with preview disabled. **Replay** plays the whole arrangement. Replay reconstructs the parameter response while the fluid continues evolving; Pause keeps the current look. A replay preview is one scene history edit.

Select a library card to edit its name/type or preview it. **Edit A/B** loads its endpoints into **Author endpoint looks**; choose a basin or tune the flame in Properties and capture the endpoint. **Update from A/B** changes the selected object, while **Save as new** creates an independent object. **+ New** opens endpoint authoring for a new state, transition or effect. A State holds B; a Transition travels A → B; an Effect rises toward B then returns to its underlying layers. Names are optional. Missing-cover endpoints show a small striped A/B placeholder; recapture the look to give it a cover.

Selected transitions/effects offer **Fill phase** as a percentage of its recorded span, **Fixed seconds**, or **Observed progress** as a percentage of the observed progression. Unknown progress or unknown live phase lengths use authored seconds. The editor reports the actual recorded span and warns when a longer response will be interrupted by the next phase. Finished always gets its full authored duration after inference completes. The optional **All response durations** multiplier in **Preview flare & timing** stretches every response. States hold their endpoint regardless of timing.

**Recording & files** contains Latest run, Demo recording, Follow next ImageGen and arrangement import/export. Follow observes the next run started through the normal Generate panel. A failed recording reports its actual outcome; its detailed terminal error is available in this section. Arrangement edits pause replay/following; arm Follow again for a subsequent run. An optional preview flare captures the current Properties look with the checked endpoint parameters, then settles back onto the continuing phase response.

The cockpit frames an existing flame once on opening. **Frame flame** uses the ordinary scene framing operation again; normal orbit and Properties editing remain available.

Captured endpoints immediately select a compact name derived from their values and a portrait of the current evolved flame. A/B portraits and shared basin covers use the same front-facing domain framing. The capture borrows the view briefly and restores it without stepping or resetting the fluid. Cold fields or unavailable capture routes keep the saved settings and report a pending portrait. Saved states show B; transitions show both endpoints. Explicit blend and arrangement exports embed portraits for reopening on another machine; live replay retains only short image references.

The Properties basin browser shows shared covers. Save basin captures the current field; it never waits through a new simulation warmup. Older basins can be backfilled through `scripts/backfill-basin-portraits.mjs --output <receipt-directory> --steps 60` under Greenroom. The batch preserves authored grid and rendering settings, records current compatibility projection/clamps and appearance mode, and reports each missing or failed cover separately. Replay runs no inference; it does not reconstruct an evolved fluid checkpoint.

The initial recording is an illustrated demo, labelled as such. Klein's real intermediate previews are approximate latent RGB projections, not fully decoded intermediate images. Stages without known progress show no percentage.

**Save arrangement** writes objects, phase stacks, the recording with preview pixels, and the flare to one JSON file. **Open arrangement** restores it. A file without a recording says so; choose **Demo recording** or an observed run explicitly. New exports use `kaminos.inference-flame.v2`; v1 files import their stage recipes as phase-fitted transitions, with an authored-duration Finished transition. Older readers reject v2 instead of silently omitting its stacks. File export retains recordings across page sessions; the in-page event store is temporary. Preview computation is requested only when Follow is armed at generation admission. Pausing Follow stops observing previews; a pipeline that already received the callback can still perform its remaining preview work until generation ends.

For agent use, the same operations are available through `window.kaminosWorkbenchExperiments.invoke`: `response.assign`, `response.captureFlare`, `response.previewStage`, `response.play`, `response.seek`, `response.pause`, `response.follow`, `response.export`, and `response.restore`. An experiment can open with `{arrangement, blend}` inputs, or `{arrangementUrl}` pointing to a saved JSON arrangement. The URL form fetches the exact file and reports failure rather than silently using the demo. Opening an arrangement does not automatically apply its looks; Replay or seeking applies them.

Object operations are `response.saveBlendObject`, `response.updateBlendObject`, `response.editObject`, `response.renameObject`, and `response.deleteObject`; direct `response.saveObject`/`response.updateObject` accept explicit recipes. Stack operations are `response.addLayer`, `response.updateLayer`, `response.moveLayer`, and `response.removeLayer`. `response.timeScale` sets the global duration multiplier. A saved object still used by a layer cannot be deleted. The retained direct-stage `response.assign` API continues observed-progress easing through unassigned successor phases.
