# Node application host: serving and authoring persistence

Run the Node host from the owning checkout with explicit application and state roots:

```sh
node serve.mjs --repo-root /path/to/kaminos --state-root /path/to/consumer-state --port 8100 --startup-report /path/to/startup.json
```

`npm start -- --state-root /path/to/consumer-state` supplies the current checkout as `--repo-root`. The default state directory is `~/.local/state/kaminos/node-app`; supplying a directory keeps concurrent consumers independent. The default bind address is `127.0.0.1`. Port `0` chooses an available port and records the actual URL in the startup report. Startup failures also write the selected report. SIGINT/SIGTERM stops the server without deleting persistent state.

This profile serves the application and its installed dependencies, prepared SAM/Klein/TRELLIS packages, images, generated mesh origins, existing basin libraries and basic scene documents. It is an implementation stage of the ordinary application service, rather than a complete replacement for every `serve.py` service. Calls outside the implemented profile return an explicit error. Basin writes and cockpit-layout services, image preparation, pipeline execution and the shared scene library are still outside this profile. The existing page requests some of those services; its corresponding warnings are outstanding integration work.

The implemented routes are:

- Static files from `--repo-root`, and `/node_modules/` from the actual dependency directory reached through that checkout. Runtime config reports that resolved dependency directory. Other static and asset symlinks cannot leave their mounted roots.
- `/api/runtime-config`, `/api/roots` and `/api/browse` for the named caller roots.
- `/api/ingest-image`, `/api/assets?kind=image`, `/api/authoring-assets?collection=image-inbox` and `/api/read`. PNG, JPEG and WebP bytes retain their complete original display names and content digests. Uploading the same image is idempotent; changed bytes create a different asset.
- `/api/ingest-mesh` and the `generated-meshes` authoring collection. GLB container version, length, first JSON chunk and chunk boundaries are validated; the existing browser loader owns semantic mesh validation. Stored bytes are published atomically by their digest.
- `/api/mesh-generation-origin` stores the existing `kaminos.asset-generation.v1` producer metadata for an ingested GLB and returns `kaminos.mesh-generation-origin.v1`. Digest, canonical source and byte count must match the stored artifact; a run id, input digest, route and successful producer receipt validation are required. The service stores that producer assertion; it does not itself verify model execution. Additive producer fields are retained. Browse and the authoring catalog expose the authored name and generation data after restart. Invalid or corrupt origins produce visible catalog warnings rather than inferred provenance.
- `/api/save-scene` and reading/browsing `scenes`. Scene data, including additive fields, is preserved. Named Save As returns 409 when a file exists until the caller explicitly confirms overwrite. Save can use its existing filename.
- GET/HEAD `/api/volume-settings-presets` lists the mounted basin library, including earlier and held versions and explicit damaged or incompatible entries. GET/HEAD `/api/volume-settings-preset?id=<content-id-or-alias>` reads an existing basin and projects it through the checkout's `volume-settings-preset-schema-v2.json`. Source content IDs and hashes are verified before projection; schema-owned additive defaults, retired controls, foreign controls and unsupported choices carry projection receipts. Reading does not rewrite stored basins. POST preset writes remain unsupported (501).

The private state directory contains `assets/images/inbox`, `assets/generated-meshes`, `scenes` and `scratch`. `--root id=/path/to/directory` replaces or adds a browse root. The host reports the effective roots; it does not discover other stores or silently fall back to a nearby checkout.

Mount existing basins explicitly with `--volume-settings-store /path/to/local-basins --shared-basin-store /path/to/shared-library`. Environment defaults are `KAMINOS_VOLUME_SETTINGS_STORE` and `KAMINOS_SHARED_BASIN_STORE`; CLI paths take precedence, and `--no-shared-basin-store` disables an inherited shared layer. With no options, the host creates a local `volume-settings` directory under its private state root and uses no shared layer. An empty new directory is an empty library; it does not stand in for an unmounted existing library. A configured missing store fails visibly. Runtime config and index/error responses name the effective layers. The shared library owns current label pointers, including unavailable current versions; a readable displaced local version is listed as earlier instead of silently replacing the shared pointer. Direct content-ID reads search local then shared. Existing content hashes retain Python's integer/float JSON distinction, so reading a stored `1.0` does not change its identity to the hash of `1`.

Each Node generation run is published as one complete, immutable directory in `.<mesh-sha256>.glb.origins/<run-id-sha256>/origin.json`. Directory rename publishes its complete record without replacing an existing nonempty run directory. Concurrent hosts can retain different runs for the same mesh without replacing an aggregate file. Identical retries are idempotent; conflicting reuse of a run id returns409. The published directory's change time records its rename into place and selects the catalog name/provenance, with a deterministic digest tie-break for equal times. Temporary-record write time is not publication order. Repeating an identical request does not reorder the displayed origin. The Node host also reads existing `kaminos.mesh-generation-origins.v1` Python aggregates and earlier Node file-only records; a new directory publication takes precedence over those imported records. New Node records are not readable by the Python server; simultaneous Python/Node or old/new Node writers to one store are outside this profile. Choose a Node-owned store or transfer an existing store to Node. Mesh bytes remain available after an origin error, supporting the existing callback's persistence retry without repeating inference.

An existing prepared SAM packet can be mounted explicitly:

```sh
node serve.mjs --repo-root /path/to/kaminos --state-root /path/to/consumer-state --sam3-packet-root /path/to/packet
```

The manifest and packet files are served beneath `/sam3-packet/`, with HEAD and single byte-range requests. `runtime-config.sam3` names the mount and whether its manifest exists; the model loader still validates the model itself. This mount performs no preparation or model computation and starts no Python process. Browser JS/Wasm retains model ownership.

The existing Klein and TRELLIS consumers can use prepared packages mounted with `--klein-weights-root /path/to/klein` and `--trellis-checkpoint-root /path/to/checkpoints`. The matching environment defaults are `KAMINOS_KLEIN_WEIGHTS_ROOT` and `KAMINOS_TRELLIS_CHECKPOINT_ROOT`; explicit CLI paths take precedence. Files stream through `/klein-weights/` and `/trellis-checkpoints/`, including exact single byte-range responses for Klein token embeddings. Runtime config preserves the existing `klein.weightsUrl` and `trellisPage.checkpointUrl` consumer fields and reports the caller's effective model roots. Klein `mounted` means all three `te`, `dit` and `vae` manifests are present inside the mount. TRELLIS `mounted` means its manifest is present inside the mount; `manifestSha256` identifies those complete raw manifest bytes. An absent option returns `null`; a missing/partial configured package reports `mounted:false`, without discovering or substituting another directory. The model loader still validates the manifest and tensors and owns computation. These mounts do not download, prepare or execute a model.

Focused verification uses `npm test -- --only tests/node-app-host.mjs,tests/node-app-host-cli.mjs,tests/node-mesh-origins.mjs,tests/node-model-mounts.mjs,tests/node-volume-presets.mjs`. The Node source and CLI tests need no Python runtime. Whole-application or native model acceptance still needs the actual consumer through this service; static/API tests alone do not establish it.
