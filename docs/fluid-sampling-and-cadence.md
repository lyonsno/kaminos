# Finite PBF sampling and playback

The `lazarus/finite-pbf` contribution keeps particle sampling separate from water amount. `resolution` is samples per world unit (spacing `1/resolution`); `blockWidth` is the world width of the cube. Their product must be an integer. Defaults retain the previous unit-width cube. Holding width while increasing resolution refines the same amount of water; holding resolution while shrinking width changes drop amount/count without changing local spacing or radii. The shallow puddle remains a separate fixed `3 × 1/8 × 1` volume and requires resolution divisible by eight. Width must fit the existing collision box. Other positive integer resolutions are allowed for drop/dam; eight is a UI increment, not a claimed GPU optimization or universal quality floor.

`describeFingerFluidBoxReference` and `describeLazarusFiniteSetup` calculate the exact proposed count/volume/spacing/support without allocating the particle array. The allocator consumes that geometry. Sharing settings and live scalar edits also avoid population allocation. Only applying a changed setup creates new particles. Invalid lattice geometry, typed-array capacity, material controls or the existing viscosity convex-mixing condition fail explicitly before replacing active water.

PBF support follows particle volume: `h = .185 cbrt(spacing³/baseVolume)`, where `baseVolume = (64π/315) .185³/24.3`. Consequently `h/spacing ≈ 3.3640491076`. Collision radius is half the spacing. The shown base rendering radius `.046 cbrt(particleVolumeScale)` is not the final surface footprint: the accumulation shader modifies it using density and surface classification. Nominal diffusion scales the capped viscosity blend by `(dt/(1/60))(.185/h)²`; this is moment scaling, not an SI viscosity calibration.

The preview is a selectable **initial central cross-section of the block**, not evolved solver state. It shows collision-sized semitransparent dots, a selected particle's density-support circle and relative poly6 weights in the slice. Its neighbor count includes all other initial block particles inside the actual three-dimensional support sphere. The independently placed puddle is not drawn in this block slice. No GPU readback, particle history or animation pump is involved.

The bottom transport offers two effective clock modes. `wall_time` preserves the original simulated-seconds/wall-seconds rate and accrues elapsed time. `render_cadence` interprets the same rate as fixed ticks per drawn frame: 1 means one tick, .25 one tick per four draws, 2 two ticks per draw. Physics `dt` stays fixed in both. Switching mode resets elapsed-time credit; paused time does not accrue. Drawn-frame mode deliberately slows simulated time when drawing is slow; it is not a faster solver, a real-time guarantee, or a GPU-completion gate. The host retains its existing frame loop. Exact manual stepping, physical-time seeking and sequence frame schedules remain independent of playback cadence.

The finite host's optional `setPlaybackMode` and effective `clock.playbackMode` accompany its existing rate capability. Generic transport consumers without a cadence capability hide this choice. Source is stacked on the named Hotwet numerical host; current-main host adoption belongs to Hotwet. Existing operator smokes and stores are preserved by using a separate source/server namespace.
